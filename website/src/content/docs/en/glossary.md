These are course definitions. Teams may use different names for test scopes; agree on the boundary and purpose, not just the label.

| English | Русский | Meaning |
| --- | --- | --- |
| Requirement | Требование | The agreed behavior or constraint. |
| Test oracle | Тестовый оракул | A source used to determine the expected result. |
| Expected result | Ожидаемый результат | What should happen according to the oracle. |
| Actual result | Фактический результат | What we observe when we run the system. |
| Defect | Дефект | A flaw that can make behavior diverge from a requirement. |
| Failure | Отказ / наблюдаемое нарушение | An observed inability to perform the required behavior. A failing test can also be caused by a bad test or environment. |
| Assertion | Утверждение в тесте | An executable comparison with an expected condition. |
| Boundary-value analysis | Анализ граничных значений | Selecting examples at and around a decision boundary. |
| Regression testing | Регрессионное тестирование | Checking for unintended behavior changes after modifications. |
| Unit test | Модульный тест | A test of a small isolated unit, such as our pure function. |
| Integration test | Интеграционный тест | A test of interactions between components or systems. |
| End-to-end test | Сквозной тест | A test of a complete journey within a declared system boundary; a UI is not required. |
| Risk | Риск | A possible adverse outcome, considered through impact and likelihood. |
| Test evidence | Свидетельства тестирования | Observations and artifacts that support a bounded conclusion. |

## More lecture terms

| English | Русский | Meaning |
| --- | --- | --- |
| Static testing | Статическое тестирование | Evaluating a work product without executing the software. |
| Dynamic testing | Динамическое тестирование | Evaluating behavior by executing software. |
| Equivalence partitioning | Классы эквивалентности | Grouping inputs expected to behave similarly for a selected rule. |
| Decision table | Таблица решений | Mapping combinations of conditions to expected outcomes. |
| Pairwise testing | Попарное тестирование | Selecting combinations that cover each pair of factor values. |
| Exploratory testing | Исследовательское тестирование | Learning, designing and executing tests together around a mission. |
| Test double | Тестовая замена | A replacement collaborator with explicitly limited behavior. |
| Negative test case | Негативный тест-кейс | Checks rejection or recovery; correct handling means the case passes. |
| Confirmation testing | Подтверждение исправления | Checking that a specific defect has been fixed. |
| Smoke suite | Smoke-набор | A selected set of critical checks used to decide whether to continue. |
| Severity | Серьёзность | The degree of impact of a problem. |
| Priority | Приоритет | The order or urgency of addressing work in context. |
| Blocked | Заблокирован | Cannot execute meaningfully because a prerequisite is unavailable. |
| Flaky result | Нестабильный результат | Inconsistent outcomes requiring investigation of product, test and environment. |
| Test isolation | Изоляция тестов | Preventing unintended interference through shared state or resources. |
| Entry / exit criteria | Критерии входа / выхода | Agreed conditions for beginning or completing a testing activity. |
