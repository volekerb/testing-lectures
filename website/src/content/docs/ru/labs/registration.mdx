## Согласуйте правило

`isRegistrationOpen(registered, capacity)` возвращает `true` тогда и только тогда, когда `registered < capacity`. Аргументы являются безопасными целыми числами: `registered >= 0`, `capacity >= 1`. Некорректный ввод вызывает `TypeError`. Если вместимость уже превышена, результат равен `false`.

Составьте таблицу для 9, 10 и 11 участников при вместимости 10. Запишите ожидаемые результаты **до** запуска проверок. Функция не резервирует и не сохраняет место.

## Запустите исходные тесты

```sh
node --version
node --test starter/registration.test.mjs
```

Два исходных теста проходят. Прочитайте их названия и входные данные. Для какой строки вашей таблицы нет теста?

## Получите содержательное падение

Откройте `starter/registration.test.mjs`. Добавьте тест для случая, когда число участников равно вместимости. С помощью `assert.equal` сравните логический результат с требованием.

```sh
node --test starter/registration.test.mjs
```

Сохраните вывод. В нём должно быть ожидаемое `false` и фактическое `true`. Если вместо этого возникла ошибка синтаксиса или импорта, сначала исправьте её. Не меняйте ожидаемый результат ради зелёного теста.

## Внесите минимальное исправление

Измените `starter/registration.mjs`, чтобы случай равенства соответствовал правилу. Сохраните свой тест и повторите запуск, затем выполните независимые примеры контракта:

```sh
node --test starter/registration.test.mjs
node check.mjs
```

После исправления должны пройти ваши тесты и все **шесть** проверок контракта. На исходном коде `node check.mjs` специально проваливает два примера равенства. Это часть упражнения, а не ошибка настройки.

## Подготовьте свидетельства

Для преподавателя или самопроверки подготовьте пять результатов:

1. Таблицу прогнозов и правило, на котором она основана.
2. Новый тест и вывод его падения до исправления.
3. Минимальное изменение реализации и успешный вывод после него.
4. [Воспроизводимый отчёт о дефекте](../../lessons/foundations/#опишите-дефект-так-чтобы-его-воспроизвели).
5. Два непроверенных риска, следующую проверку и объяснение её приоритета.

| Критерий | Баллы |
| --- | --- |
| Верные прогнозы с указанием оракула | 2 |
| Граничный тест падает по нужной причине | 2 |
| Минимальное исправление и успешные регрессионные проверки | 2 |
| Воспроизводимый отчёт с возможным влиянием | 2 |
| Границы проверки и обоснованный следующий тест | 2 |
