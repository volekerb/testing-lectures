# Последнее место

[English version](README.md)

Запись разрешена только при `registered < capacity`. Аргументы: безопасные целые числа,
`registered >= 0`, `capacity >= 1`. Некорректный ввод вызывает `TypeError`. Число
зарегистрированных выше вместимости допустимо: функция должна вернуть `false`.
Функция принимает решение, но не резервирует место, не меняет базу и не обрабатывает
конкурентные запросы.

**Нужно:** Node.js 24. Установка пакетов, API-ключи и внешние сервисы не требуются.
Выполняйте команды из этой папки (в том числе после распаковки архива практики).

1. Запустите `node --test starter/registration.test.mjs`. Оба исходных теста пройдут.
2. Запишите ожидаемые результаты для 9, 10 и 11 участников при вместимости 10.
3. Добавьте тест для ровно 10 участников. Повторите запуск и сохраните ошибку.
4. Внесите минимальное исправление в `starter/registration.mjs`. Запустите тесты снова.
5. Выполните `node check.mjs`. Все шесть проверок контракта должны пройти.
6. Подготовьте новый тест, изменение кода, вывод до и после, отчёт о дефекте и два риска,
   которые этот тест функции не покрывает. Обоснуйте приоритет следующей проверки.

На исходном коде `node check.mjs` специально завершается с ошибкой. Зелёный исходный
набор доказывает результат двух примеров, а не корректность всей реализации.

Дополнительно: проверьте некорректный ввод и другую вместимость; объясните, почему два
одновременных запроса могут увидеть одно свободное место. Базу данных писать не нужно.

На сайте есть подробный разбор. В репозитории можно выполнить
`node check.mjs --solution`; в скачиваемом архиве эталонного решения нет.

## Шаблон отчёта о дефекте

- **Заголовок:** поведение и условие, при котором оно возникает.
- **Окружение:** версия Node и ревизия репозитория (или дата скачивания практики).
- **Шаги/ввод:** минимальный воспроизводимый вызов.
- **Ожидаемый результат:** значение и правило, из которого оно следует.
- **Фактический результат:** наблюдаемое значение и вывод теста.
- **Влияние:** возможное последствие; не выдавайте гипотезу о продакшене за проверенный факт.

## Самопроверка (10 баллов)

| Свидетельство | Баллы |
| --- | --- |
| Результаты для 9, 10 и 11 с объяснением правила | 2 |
| Граничный тест падает до исправления | 2 |
| Минимальное исправление; свои тесты и проверки контракта проходят | 2 |
| Воспроизводимый отчёт о дефекте с описанием влияния | 2 |
| Два непроверенных риска и обоснованная следующая проверка | 2 |

Критерии нужны для обсуждения и самопроверки; практика ничего не отправляет на сервер.
